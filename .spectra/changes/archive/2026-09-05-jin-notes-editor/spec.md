# Jin Notes Editor — Cozy Writing Surface

## Objective

Make the existing Notes editor feel like a calm Jin writing desk: one continuous warm paper surface, a strong ink-led title, comfortable editorial typography, restrained indigo interactions, and quiet formatting and save feedback. The change must be immediately visible in a real note while keeping every existing editing contract intact.

The visual direction comes from the Jin mark: warm fibrous paper and black ink carry the writing; indigo identifies focus, links, and active modes; vermilion remains reserved for capture or consequential intent. Do not place the editor inside a card or rounded bordered container. Space, type, a thin rule, and tonal shifts establish hierarchy.

## Implementation contract

1. **Create dedicated editor roles in `jin-gui/src/styles/tokens.css`.** Add adaptive, light/dark-safe roles for the writing paper, ink, muted ink, toolbar wash/rule, selection/focus tint, quote rule, code wash, and save-state colors. Add geometry roles for an approximately `66ch` prose measure, `1.125rem` body text, and about `1.7` line height. Component styles must continue to use tokens only. Keep both system-dark and explicit `data-appearance="dark"` variants aligned.

2. **Turn the detail pane into one continuous writing surface in `jin-gui/src/styles/browse.css`.** The pane, CodeMirror root, editor wrapper, scroll region, and Reading view share the same paper role; remove the current nested white rectangle. There is no outer card, rounded document boundary, shadow, or full-box border. Center title, prose, tags, links, and footer on a comfortable measure at wide sizes, while the toolbar may use the wider existing reading width so all real commands remain reachable.

3. **Strengthen the writing hierarchy in `browse.css`.** Increase the editable title to a clearly expressive display size and give it generous breathing room. Keep it borderless at rest; on focus use a straight indigo/ink underline plus a visible focus treatment without rounding the title into a field. Render body prose at the new editorial size and leading, with readable paragraph rhythm. Use the display face selectively for the note title and Markdown headings; body copy stays in the text face. Brand links and caret with indigo, quotes with a restrained indigo rule and muted ink, and inline/fenced code with a warm tonal wash. Apply the same measure and typography to Write and Read modes so toggling does not cause a large horizontal jump.

4. **Group the real toolbar controls in `jin-gui/src/lib/notes/editor.ts` and style them in `browse.css`.** Preserve every existing button and command, but wrap the current structure, inline, list, block, and mode controls into labelled `role="group"` clusters using `.cm-toolbar__group` hooks. Groups may use a quiet wash and small control rounding; the toolbar and editor itself remain open and unboxed. Keep the toolbar role/label, native tooltips, keyboard access, horizontal reachability, Focus and Typewriter `aria-pressed` states, and the existing Read/Edit toggle and flush behavior. Do not add commands, menus, formatting semantics, or a second editor.

5. **Make editing state legible without becoming noisy.** In `editor.ts`, expose the existing real save lifecycle on the status element with `data-save-state="saving|saved|failed|paused"` as the displayed text changes. Style the footer as a quiet continuation of the paper with real word/character count, reading time, and textual save state. Saved may recede; saving, failure, and conflict-paused states must remain readily perceptible through text plus a non-color cue. Initial state remains truthful; do not invent a save result.

6. **Keep note metadata and related content in the writing flow.** In `browse.css` (and `jin-gui/src/lib/notes/render.ts` only if a class/state hook is required), make tags a quiet metadata line and links/backlinks a restrained endnote section on the same prose measure. Keep the real Active/archived status, attachment, typed-link, and History controls and all callbacks. The common Active state should be visually quiet beside the title, while non-active state remains clear.

7. **Make the surface reflow in `jin-gui/src/styles/a11y.css` and responsive rules in `browse.css`.** At 320 and 390 CSS px the writing area uses the available width with useful inline padding, the title/status wrap, toolbar groups remain reachable without page horizontal scroll, and footer content wraps without collision. At AX5/310% text, toolbar groups and mode controls wrap into a readable vertical flow, document content loses restrictive fixed/min dimensions, and the page has no horizontal clipping. Preserve the existing manual appearance, text-scale, reduced-motion, reduced-transparency, increased-contrast, and forced-colors behavior; forced colors must retain boundaries/focus for toolbar groups and editor state.

8. **Add focused regression coverage.** Extend `jin-gui/src/__tests__/notes_visual_system.test.ts` for the continuous paper surface, prose measure/type tokens, open title focus, toolbar groups, responsive/AX5 reflow, and absence of an editor card boundary. Extend `jin-gui/src/__tests__/editor.test.ts` for group labels, unchanged command controls, Read/Edit behavior, save-state attributes, autosave identity/caret safety, failure, and paused-conflict state. Extend `jin-gui/src/__tests__/token_discipline.test.ts` for every new adaptive role and token-only component usage.

## Acceptance criteria

- **AC1 — Continuous Jin paper:** WHEN a real note opens in Write or Read mode THEN the title, toolbar, body, and footer SHALL read as one adaptive warm paper surface without a nested white editor rectangle, rounded document border, card shadow, or fabricated texture.
- **AC2 — Editorial comfort:** WHEN a note is viewed between 760 and 1440 CSS px THEN prose SHALL use an approximately `66ch` maximum measure, `1.125rem` base size, and approximately `1.7` leading; the title and Markdown headings SHALL form a clear ink-led hierarchy and Write/Read mode SHALL retain substantially the same measure.
- **AC3 — Real toolbar, calmer form:** WHEN the formatting toolbar renders THEN all existing heading, inline, list, quote, link, Focus, Typewriter, and Read/Edit controls SHALL remain present and operative, arranged in labelled visual groups with visible keyboard focus and accurate pressed state.
- **AC4 — Writing continuity:** WHEN typing triggers the 600 ms autosave, a blur/Read toggle flushes, or a save resolves THEN the same CodeMirror `EditorView` and DOM node SHALL remain mounted, caret/selection and native undo SHALL remain intact, and no render-detail or `setDoc` operation SHALL run on the autosave path.
- **AC5 — Truthful save feedback:** WHEN save state is saving, saved, failed, or paused by a conflict THEN the footer SHALL expose the matching real text and `data-save-state`; failure and paused states SHALL be distinguishable without color alone. BEFORE any save result exists, Jin SHALL NOT claim the note is saved.
- **AC6 — Existing note contract:** WHEN users edit/revert a title, switch Read/Edit, format text, use Focus/Typewriter, attach files/events, create typed links, open History, follow links/backlinks, or resolve a conflict THEN existing callbacks, payloads, sanitization, focus, flush, and navigation behavior SHALL remain unchanged.
- **AC7 — Responsive and accessible:** WHEN Notes is exercised at 320, 390, 760, and 1440 CSS px and at AX5/310% text THEN title, status, toolbar, editor/reader, metadata, links, and footer SHALL remain readable and reachable without page horizontal scrolling or clipped meaning. WHEN forced colors or increased contrast is active THEN focus, active modes, save errors, and structural rules SHALL remain perceivable.
- **AC8 — Adaptive appearance:** WHEN appearance is light, dark, or automatic THEN the editor SHALL use its adaptive paper/ink roles with readable body, selection, code, quote, link, toolbar, and status contrast; explicit appearance choice SHALL continue to override system preference.

## Boundaries

No Rust, core, DTO, bridge, persistence, Markdown format, sanitizer, attachment, history, conflict, or navigation changes. Do not replace CodeMirror, add a second editor, add AI/slash-command/collaboration features, fabricate textures or save state, redesign Notes lists/folders again, or alter Today, Tasks, Events, Settings, or Capture. Preserve all existing controller targets/actions, editor commands and shortcuts, 600 ms debounce/flush lifecycle, note-switch mount/destroy boundary, live-preview chokepoints, caret safety, native undo/redo, and real link/action routes.

## Verification

Run focused Vitest coverage for editor, Notes controller/render, visual system, and token discipline; then `make verify-gui`. Perform deterministic Playwright MCP visual QA at `http://127.0.0.1:1420` in light/dark at 1440, 760, 390, and 320 CSS px, plus the repository AX5/310% mode. Verify Write/Read, title focus/revert, formatting, Focus, Typewriter, save success/failure/conflict, long prose/code/quote/list content, footer wrapping, console warnings, and page horizontal overflow. Browser evidence does not replace native Tauri owner sign-off.
